## ◈ Welcome to Hisaab

**Splitting expenses should be easy. Keeping track of them should be even easier.**

You pay for dinner. Your roommate covers groceries. A friend books the ride. A family member pays the electricity bill.

Before you know it, everyone's trying to remember who paid what, how much they owe, and whether someone has already settled up.

Hisaab brings those shared expenses into one place.

Instead of scattered calculations, forgotten transactions, and endless message searches, you get a central space to record spending, review your history, understand balances, and communicate with the people involved.

**Less confusion about money. More clarity between people.**

## 🎨 The design: maximalism meets glassmorphism

Hisaab isn't trying to look like another plain spreadsheet with a few buttons added to it.

Its visual direction combines **maximalism's expressive personality** with **glassmorphism's layered, translucent aesthetic**.

The goal is an interface that feels distinctive, modern, and enjoyable to use while keeping financial information understandable.

| Design element | The intention |
|---|---|
| ◈ Glassmorphism | Create depth through translucent surfaces and layered UI elements. |
| ✦ Maximalism | Give the application a bold visual identity rather than a generic dashboard appearance. |
| ⟡ Visual hierarchy | Make important information easier to find and understand. |
| ↗ Responsive design | Aim for a comfortable experience across different screen sizes. |
| ◎ Functional interactions | Make the interface useful, not just visually impressive. |

The guiding principle is simple:

**Beautiful enough to explore. Clear enough to trust. Practical enough to use.**

## 🚀 Run the project locally

Want to explore the code and run Hisaab on your own machine?

### Prerequisites

- [Node.js](https://nodejs.org/)
- npm
- A Firebase project and the required credentials for Firebase-backed functionality.
- A Gemini API key if the AI functionality requires one.

### 1. Clone the repository

```bash
git clone https://github.com/Malik-Zain-555/Hisaab.git
cd Hisaab
```

### 2. Install dependencies

If the root directory contains a `package.json`:

```bash
npm install
```

If the frontend and backend use separate package files, install their dependencies in the appropriate directories instead.

### 3. Configure environment variables

Check the project's example environment files and source configuration to identify the required variable names.

Create the appropriate local `.env` file or files and supply the credentials required by the application.

**Security note:** Never commit private API keys, service-account credentials, or other secrets to GitHub. Keep server-only credentials on the server.

### 4. Start the application

Inspect the available scripts:

```bash
npm run
```

Run the appropriate development command defined in the project. For a Vite frontend, this commonly looks like:

```bash
npm run dev
```

If the backend runs separately, start it using its own configured script.

### 5. Open Hisaab

Visit the local URL printed by the development server.

For the deployed version, use the [Hisaab live preview](https://ais-pre-fpw2tpblkoiwuedaoanbgs-742916804260.asia-southeast1.run.app/).

*The exact installation and startup commands depend on the repository's current configuration.*

## 🔐 Security and responsible development

Expense information can be sensitive. Before using an application with real financial data, its security controls should be reviewed carefully.

Important areas include:

- **Authentication:** Ensure protected features require an authenticated user.
- **Authorization:** Verify permissions on the server and database, not just in the UI.
- **Firestore rules:** Restrict access to the appropriate users and shared groups.
- **API credentials:** Keep private keys out of public frontend bundles and version control.
- **Input validation:** Validate incoming data before processing or storing it.
- **Testing:** Check that unauthorized users cannot access other users' information.

These are security considerations, not a claim that the current implementation has undergone a security audit.
